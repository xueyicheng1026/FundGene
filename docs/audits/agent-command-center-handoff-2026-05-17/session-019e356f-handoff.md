## 1. User Requirements Captured in This Session

### 1.1 Product direction

The user said the project should be substantially rethought around automation and agent-driven execution:

- FundGene should emphasize automation.
- The agent should be able to do as much work as possible after user authorization.
- The user should be able to see what the agent is doing, how it is doing it, and what tools it calls, similar in spirit to Codex.
- The current product has too many pages and feels scattered.
- The project should start by revising the product blueprint, then reshape pages and features from that blueprint.
- The product should let the user give tasks to the agent or authorize background work; the user mainly confirms, chooses, or gives additional direction.

The chosen V1 decision was recorded as:

- `L1 + L2`
- `B + B + BC + B`

Meaning:

- L1: user-directed agent tasks.
- L2: default Daily Brief automation.
- Homepage should be `Today`, not chat-first.
- Daily Brief should be generated by default and user-controllable.
- Agent process display should default to natural-language steps, with advanced tool/trace details available behind a deeper layer.
- Old modules should be demoted from primary navigation into agent tools, action targets, detail pages, or profile drilldowns.

### 1.2 Documentation and memory requirements

The user asked to modify the necessary `.md` files across the repository to prevent old context from polluting later work.

The user also explicitly asked to write the new idea into memory, then begin implementation. Multi-agent work and frontend screenshot visual checks were encouraged.

### 1.3 Today page requirements

The user later reviewed the first implementation direction and raised these issues about `/today`:

- The name `二级状态源` is bad and should be replaced.
- Components lack visual distinction.
- The page should not feel like a set of equal text blocks.
- It should present multiple kinds of information at a glance.
- It should add charts or chart-like visualizations instead of staying pure text.
- It should improve visualization, page layout, interaction, and visual friendliness.
- The frontend style should not be changed globally; existing colors, typography, and Apple-style light workbench direction should be preserved.

### 1.4 Agent page requirements

The user then required `/agent` to move closer to a Codex-like work surface:

- Components need stronger distinction.
- Left side should support session history selection and creating a new task/session.
- Middle should contain the current conversation and task input.
- Right side should show agent progress and background tasks.
- The old right-side blocks such as `当前画像` and `下一步队列` were considered low-value and should be removed or replaced.
- The workflow must be sequential: first delegate `/today` to a GPT-5.5 high worker, review and force rework if needed, then repeat the same process for `/agent`.

# FundGene Agent Command Center UX v1

日期：2026-05-17
状态：V1 UX 基线。本文档取代 `agentic-beginner-coach-ux-v1.md` 作为下一阶段产品/前端/后端协同入口。

## 1. UX 目标

FundGene V1 要从“多个金融功能模块 + 一个 AI 教练页”变成“Agent Command Center”。

用户打开产品时，不应该先看到一堆入口，而应该先看到 Agent 已经替他完成的第一轮整理：

```text
今天最重要的判断
为什么和我有关
我现在可以安全做什么
今天不要做什么
Agent 已经检查了哪些来源
```

核心体验：

> Agent 先看完，用户再确认和选择。

## 2. V1 页面 IA

一级页面只保留四个：

| 页面 | 角色 | UX 重点 |
| --- | --- | --- |
| `/today` | 默认 home / Daily Brief | 先给一个判断，不展示模块目录 |
| `/agent` | Agent Workspace | 用户布置任务，Agent 展示执行过程和结果 |
| `/automations` | 自动任务授权 | 控制 Daily Brief、组合巡检、资讯观察等 L2 自动化 |
| `/profile` | 我的资料 | 管理 Agent 判断所需的画像、组合、行为证据、学习状态和授权 |

迁移规则：

- `/dashboard` 是 `/today` 的当前实现前身。
- `/coach` 是 `/agent` 的当前实现前身。
- `/portfolio`、`/news`、`/learning`、`/simulation` 保留为工具详情页，不再做一级导航。
- `/start` 只负责登录、新用户状态判断和进入主流程。

## 3. `/today` 今日简报

`/today` 是 V1 的第一印象。它不是 dashboard，不堆数据。

首屏顺序：

1. 今日一句话判断。
2. 对我有什么影响。
3. 最多三条证据。
4. 一个主安全动作。
5. 一个或两个备选动作。
6. 今天不要做什么。
7. Agent 已检查的数据来源和生成时间。

示例结构：

```text
今天先检查组合集中度，不急着响应单条新闻。

为什么和你有关：
- 你的科技主题基金占比较高。
- 今天相关资讯主要影响成长风格预期。
- 你的风险问卷显示你对短期回撤较敏感。

建议先做：
检查组合集中度

今天不要做：
不要因为单条新闻临时清仓或追涨。
```

UX 规则：

- 一屏只突出一个主判断。
- 证据不超过三条。
- 动作必须是产品内安全动作。
- 不展示原始新闻列表作为首屏主体。
- 不使用“买入、卖出、清仓、满仓、收益确定”等语言。

## 4. `/agent` 工作台

`/agent` 不是普通聊天页，而是 Agent Run 的执行界面。

页面结构：

- 任务输入：用户布置目标。
- 对话与结果：Agent 输出解释、结论和下一步。
- 执行过程：展示 Agent 正在做什么。
- 确认卡片：需要写回资料、创建自动任务或记录行为证据时，必须让用户确认。

默认过程展示使用自然语言：

```text
正在理解任务
正在读取你的风险画像
正在检查最新组合
正在筛选相关资讯
正在评估影响路径
正在生成安全下一步
等待你确认是否写回
```

高级模式可展开：

```text
trace id
tool calls
evidence refs
worker outputs
model/fallback metadata
policy guard result
latency
```

默认不要展示 raw tool name、worker name、run id、prompt payload 或 citation key。

## 5. `/automations` 自动任务

V1 做 L2 自动化，但必须可见、可关、可解释。

MVP 自动任务：

1. 每日简报：每天自动生成 `/today` 内容。
2. 每周组合巡检：检查集中度、资产暴露和现金比例。
3. 资讯影响观察：只关注与用户画像和持仓相关的新闻/政策。
4. 行为偏差观察：生成待确认行为证据，不直接改画像。

每张自动任务卡片必须说明：

- Agent 会读取什么。
- Agent 会生成什么。
- 多久运行一次。
- 哪些内容需要用户确认后才写回。
- 安全边界是什么。

## 6. `/profile` 我的资料

`/profile` 是 Agent 的上下文仓库和授权中心，不是普通个人设置页。

信息分组：

- 账号与登录状态。
- 风险画像和问卷。
- 组合快照和最近报告。
- 行为证据和待确认画像更新。
- 学习进度和训练记录。
- 自动任务授权与数据读取范围。

UX 规则：

- 关键画像变化必须显示来源证据。
- 弱证据只进入 pending confirmation。
- 用户可以修正、拒绝或确认。
- 不把一次模拟或一句对话直接写成永久标签。

## 7. 旧模块详情页规则

旧模块不是删除，而是降级。

| 旧页面 | 新角色 |
| --- | --- |
| `/portfolio` | Agent action 的组合详情页 |
| `/news` | Agent evidence 的资讯详情页 |
| `/learning` | Agent 推荐学习动作的承接页 |
| `/simulation` | Agent 推荐训练动作的承接页 |

这些页面首屏也应遵循：

```text
Agent 判断 -> 证据 -> 安全动作 -> 原始数据/历史列表
```

不要再做成“用户自己找功能”的模块目录。

## 8. 视觉与交互原则

- 页面应安静、清晰、决策支持感强。
- 不做金融终端，不做大而全 dashboard。
- Today 适合轻量、第一屏强结论。
- Agent Workspace 适合过程感、任务流和确认卡片。
- Automations 适合权限卡片，不适合复杂流程图。
- Profile 适合事实与授权，不适合营销式叙事。
- 每次大改都要用 Playwright 截图做桌面和移动端视觉检查。

## 9. UX 验收

V1 UX 通过标准：

- 用户一进入主 home 就知道 Agent 已经做了什么。
- 用户不需要主动点新闻、组合、学习、模拟才能得到第一条判断。
- Agent Workspace 看起来像任务执行，而不是纯聊天。
- 自动任务明确可控，不像偷偷监控。
- 旧模块不再抢主导航。
- 高级 trace 提供可信度，但默认不吓到新手。
- 所有高影响写回都需要确认。
